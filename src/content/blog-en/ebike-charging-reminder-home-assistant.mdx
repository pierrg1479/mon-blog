The second bike in our house is used for commuting: a 16 km round trip (about 10 miles) to work and back. Charging it was never the problem. Remembering to do it the evening before, while the battery still has enough range, was.

The bike's display shows the remaining range, but you have to think of checking it the night before. The result: stressful departures and a few unpleasant surprises.

Now Home Assistant handles it. It reads the bike's range from the Bosch cloud and only sends a reminder when that range won't cover the next day's commute. Then charging starts on its own during off-peak hours. Here is the full setup: hardware, integration, battery percentage estimate, automation and real-world results. As a bonus, a weather alert the evening before tells you whether biking tomorrow is a good idea.

## The bike and the hardware

The bike is a [Riese & Müller Multitinker2 family](https://www.r-m.de/en-gb/bikes/multitinker2/multitinker2-family/), a compact urban cargo bike on 20-inch wheels. What matters for this article is its Bosch equipment:

- **Motor**: Bosch Performance Line PX, part of the Smart System range
- **Battery**: Bosch PowerTube 625 Wh
- **Display**: Bosch Purion 200

On the smart home side:

- **Home Assistant** with the community [Bosch eBike integration](https://github.com/Xunil99/ha-bosch-ebike), installed through HACS (version 1.19.58 in my case)
- **A Sonoff S60ZBTPF Zigbee smart plug** with power monitoring, powering the charger (I use several of them around the house, see [how smart plugs helped me cut my electricity bill](/en/blog/smart-plugs-savings-automations/))
- **The Home Assistant companion app** on the rider's phone, to receive the notifications
- **A [wall mount for the Bosch Smart System 4A charger (BPC3400)](https://www.amazon.fr/dp/B09VKZ3NPK)** (Amazon France), which holds the original charger on the garage wall. Handy, expensive for a 3D-printed part, but a perfect fit.

## How does Home Assistant know a Bosch e-bike's range?

The Bosch eBike integration reads the bike's data through Bosch's official Data Act API, using the rider's Bosch account. It creates a device with more than 70 entities in Home Assistant, including the remaining range for each assist mode.

### Which Bosch e-bikes are compatible?

This reminder only works with a Bosch Smart System motor. According to the [integration's README](https://github.com/Xunil99/ha-bosch-ebike), bikes from the previous generation (eBike System 2) are supported in alpha, but the API provides neither per-mode range nor battery data for them. The older Classic Line system is not supported at all.

That's why my own bike, a 2022 Moustache Lundi 27, doesn't get a reminder. Its Bosch Active Line Plus motor belongs to eBike System 2 and its Intuvia display isn't connected: Home Assistant has no range to read.

There is one more hard limit, especially if you are outside Europe: the integration requires a Bosch SingleKey ID account registered in the European Union. The Data Act API is only open to EU accounts, so accounts from other regions cannot authenticate.

### Installing the Bosch eBike integration

The README walks through every screen. In short:

1. Link the bike to the Bosch eBike Flow app with a SingleKey ID account.
2. On the [Bosch Data Act portal](https://portal.bosch-ebike.com/data-act/app), create an "app" (for example "Home Assistant") using the two `my.home-assistant.io` addresses listed in the README. Write down the Client-ID you get.
3. In HACS, install the Bosch eBike integration, then restart Home Assistant.
4. In Bosch's eBike Manager, under Data Act, activate the service for your app: Home Assistant opens, paste the Client-ID and sign in to your Bosch account.
5. Still in the eBike Manager, turn on data sharing for the bike, then reload the integration in Home Assistant.

Step 5 is the easiest one to miss: without it, the integration is installed but no entities show up.

### The sensors that matter for charging

Values recorded on an evening when charging was needed:

| Sensor | Value | What I use it for |
|---|---|---|
| Turbo range | 15 km | Triggers the reminder below 20 km |
| Eco, Auto and middle mode range | 32, 24 and 19 km | Battery percentage estimate |
| Estimated full-battery range | 136 km (4.6 Wh/km) | Information only |
| Battery charge cycles | 5.6 | Tracking wear |
| Odometer | 306 km | Information only |

### The limits: no percentage, no real time

In my setup, the integration provides no usable battery percentage: the "Last Ride Battery (%)" sensor stays "unknown". The README explains that a live state of charge requires an ESP32-based Bluetooth bridge, which I haven't installed.

The values aren't real time either. The integration polls Bosch every 10 minutes, but the range only changes after the bike has synced its data. That sync happens when the phone, running the eBike Flow app, connects to the bike as it is switched on. In our case, the range is updated in the morning when leaving and again on the way back.

## Estimating the battery percentage from the range

To show a percentage in the notification and on the dashboard, I created a Template helper (Settings > Devices & services > Helpers > Create helper > Template > Sensor). It adds up the four ranges and divides the total by 236.2 km. Unit: %, device class: Battery.

236.2 km is roughly the sum of the four ranges with a full battery. On days when the battery was full or nearly full, I recorded between 233 and 246 km, hence the 100% cap. It is an estimate: it assumes the range drops at the same pace as the charge.

To adapt it to your bike, write down the sum of your ranges right after a full charge and replace 236.2 with your own value. Mode names also depend on the bike: one of mine is called `a100m40030`, the internal name reported by Bosch.

<summary>View YAML code</summary>

```jinja
{% set ids = ['sensor.performance_line_px_reachable_range_eco',
              'sensor.performance_line_px_reachable_range_auto',
              'sensor.performance_line_px_reachable_range_a100m40030',
              'sensor.performance_line_px_reachable_range_turbo'] %}
{% set vals = ids | map('states') | select('is_number') | map('float') | list %}
{% if vals | count == 4 %}
  {{ [((vals | sum) / 236.2 * 100) | round(0), 100] | min }}
{% else %}
  {{ none }}
{% endif %}
```

## The rule: only remind when the range won't cover tomorrow

A notification sent every evening ends up being ignored. So the automation only sends a reminder when charging is actually needed.

### Why 20 km in Turbo mode?

The commute is 16 km round trip. I add about 25% margin, which gives a 20 km threshold (about 12 miles). I use Turbo mode because it uses the most energy: if the Turbo range is enough, every other mode is enough too.

### A different message depending on the next day

Every evening at 8 pm, Home Assistant checks the Turbo range. If it is below 20 km:

- Sunday to Thursday, the message is direct: "charge your bike", with the remaining range and a reminder that tomorrow's commute is 16 km;
- Friday and Saturday, there is no commute the next day: the message flags a low battery and suggests charging over the weekend.

### No reminder during holidays

The automation doesn't run when the house is in Away, Holiday or Holiday-at-home mode. These modes are a dropdown helper (`input_select.mode_maison`).

### If sending fails: 3 attempts, then an alert

In Home Assistant, a phone's notify entity stores the time of the last message sent. The automation uses it to check that Home Assistant was able to send the reminder.

Note that this doesn't prove the phone received it: the state changes as soon as the notification service accepts the message. If the phone is offline, the send still counts as successful, so there is no retry and no alert.

If the state hasn't changed, the send failed: Home Assistant retries every 5 minutes, up to 3 times. After 3 failures, it sends an alert to my own phone so I can pass the message on. In the runs I was able to check, the first attempt always went through.

<details>
<summary>View YAML code</summary>

```yaml
alias: E-bike - Charging reminder
description: >-
  Every evening at 8 pm, notify if the Turbo range is below 20 km
  (16 km round-trip commute + about 25% margin).
  Firm message Sunday to Thursday, relaxed on Friday and Saturday.
  3 attempts if sending fails, then an alert.
triggers:
  - trigger: time
    at: "20:00:00"
conditions:
  - condition: numeric_state
    entity_id: sensor.performance_line_px_reachable_range_turbo
    below: 20
  - condition: not
    conditions:
      - condition: state
        entity_id: input_select.house_mode
        state:
          - Away
          - Holiday
          - Holiday at home
variables:
  last_sent_before: "{{ states('notify.rider_phone') }}"
actions:
  - repeat:
      sequence:
        - action: notify.send_message
          continue_on_error: true
          target:
            entity_id: notify.rider_phone
          data:
            title: "{% if now().weekday() in [4, 5] %}Low e-bike battery{% else %}Time to charge your e-bike{% endif %}"
            message: "{% set km = states('sensor.performance_line_px_reachable_range_turbo') | float(0) | round(0) | int %}{% set pct = states('sensor.estimated_bike_battery') %}{% if now().weekday() in [4, 5] %}{{ km }} km left in Turbo (≈ {{ pct }}%). No commute tomorrow, but you can charge it over the weekend.{% else %}{{ km }} km left in Turbo (≈ {{ pct }}%) and tomorrow's commute is 16.{% endif %}"
        - if:
            - condition: template
              value_template: "{{ states('notify.rider_phone') == last_sent_before and repeat.index < 3 }}"
          then:
            - delay: "00:05:00"
      until:
        - condition: template
          value_template: "{{ states('notify.rider_phone') != last_sent_before or repeat.index >= 3 }}"
  - if:
      - condition: template
        value_template: "{{ states('notify.rider_phone') == last_sent_before }}"
    then:
      - action: notify.send_message
        target:
          entity_id: notify.my_phone
        data:
          title: E-bike reminder not sent
          message: "3 attempts failed. Turbo range: {{ states('sensor.performance_line_px_reachable_range_turbo') | float(0) | round(0) | int }} km. Remember to charge the bike."
mode: single
```

</details>

## Then charging starts on its own during off-peak hours

Once the reminder arrives, there is only one thing left to do: plug in the charger. The smart plug stays off until 10:01 pm, when my off-peak tariff starts. Home Assistant then turns it on, and cuts it once power stays below 5 W for 2 minutes, which means charging is done. I covered that automation in [Automating E-Bike Charging During Off-Peak Hours](/en/blog/automating-ebike-charging-off-peak-hours/).

Since that article, I made the automation more robust. If the Zigbee plug doesn't respond at 10:01 pm, Home Assistant makes 3 attempts, tries again around 10:15 pm, and only alerts me if it still doesn't respond.

Here is the full chain on a real evening:

1. **8:00 pm**: 16 km left in Turbo (≈ 41%), the reminder goes out.
2. **10:01 pm**: the plug turns on, the charger draws about 165 W.
3. **Around 12:30 am**: power drops and the plug turns off. The charge used 0.38 kWh on the plug's meter.
4. **Next morning**: after syncing, the bike shows 40 km of Turbo range.

<div class="callout callout--warning">
  <p class="callout__content"><strong>Battery safety:</strong> Bosch recommends charging in a dry place fitted with smoke detectors, between 0 and 40 °C (32 to 104 °F), with a compatible charger, and not leaving the battery unattended while charging (<a href="https://www.bosch-ebike.com/fileadmin/EBC/Service/Downloads/Akku_Guide/Akku_Guide/Bosch-eBike-Battery-Guide-EN-US.pdf">Bosch battery guide</a>). Scheduled overnight charging departs from that last recommendation. In my case, charging happens in the garage, which has a smoke detector connected to Home Assistant, with the original charger, and the plug cuts power as soon as charging ends. Make your own call based on your setup.</p>

## My experience so far

Home Assistant keeps the details of the last five runs. Over those five evenings, the reminder went out twice and stayed silent the other three times, since the range was sufficient.

It hasn't saved us from a dead battery as such. But it removed the morning stress and the unpleasant surprises when leaving. And it was adopted at home without any pushback.

One limit to keep in mind: the reminder reads the last synced value. If the bike hasn't synced since its last ride, the range read at 8 pm may be higher than reality.

## Bonus: will it rain on tomorrow's bike commute?

A second Home Assistant automation also runs at 8 pm and reads tomorrow's hourly forecast for the commuting hours. If rain or frost is forecast, it sends a notification that says when, how heavy, and what gear to bring.

Battery and weather are both checked at the same time, the evening before.

### Two weather sources to judge reliability

The automation queries two weather integrations with the [`weather.get_forecasts`](https://www.home-assistant.io/integrations/weather/) action (hourly forecasts): [Météo-France](https://www.home-assistant.io/integrations/meteo_france/), the French national weather service, and [Met.no](https://www.home-assistant.io/integrations/met/), the Norwegian Meteorological Institute. It looks at tomorrow from 8 am to 7 pm, which covers both legs of the commute. Outside France, swap Météo-France for any other weather integration.

An hour counts as rainy if the forecast shows precipitation or a rain, snow or hail condition. Then:

- if both sources forecast rain, the risk is "high";
- if only one does, the risk is "uncertain" and the message says which one;
- consecutive rainy hours are grouped: "all day", "between 8:00 and 10:00" or "for 1 hour from 17:00 to 18:00".

### From rain intensity to the gear to bring

Intensity is based on the wettest hour, not on the daily total. It decides the advice at the end of the notification:

| Forecast (8 am to 7 pm) | Intensity | Advice in the notification |
|---|---|---|
| Peak below 1 mm/h | Light rain | A rain jacket should do |
| Peak of 1 to 4 mm/h | Moderate rain | Full rain gear needed |
| Peak of 4 mm/h or more | Heavy rain | Better leave the bike at home |
| 0 °C (32 °F) or below | Frost | Risk of ice on the road |

### Only on commuting days

The automation only runs Sunday to Thursday, and only if an alarm is set for the next day on the rider's phone. The Home Assistant Android app reports that alarm in a [Next Alarm sensor](https://companion.home-assistant.io/docs/core/sensors/): no alarm, no commute, no notification.

As with the charging reminder, silence means all is well: with no rain or frost forecast, nothing is sent.

### A notification that clears itself

The notification carries a [tag](https://companion.home-assistant.io/docs/notifications/notifications-basic/) (`weather_tomorrow`) and a timeout calculated so it disappears the next day at 7 pm, at the end of the analysed window. Tapping it opens the Météo-France weather card in the app.

<details>
<summary>View YAML code</summary>

```yaml
alias: E-bike - Rain or frost tomorrow
description: >-
  Sunday to Thursday at 8 pm, if an alarm is set for the next day.
  Notify if rain or frost (≤ 0 °C) is forecast between 8 am and 7 pm
  the next day. High risk if Météo-France and Met.no both forecast rain,
  uncertain if only one does. Intensity from the hourly peak:
  light < 1 mm/h, moderate 1 to 4 mm/h, heavy ≥ 4 mm/h.
triggers:
  - trigger: time
    at: "20:00:00"
conditions:
  - condition: time
    weekday: [sun, mon, tue, wed, thu]
  - alias: Alarm set for tomorrow on the rider's phone
    condition: template
    value_template: >-
      {% set r = states('sensor.rider_phone_next_alarm') | as_datetime(none) %}{{ r is not none and as_local(r).date() == (now() + timedelta(days=1)).date() }}
actions:
  - alias: Read hourly forecasts (unavailable weather entities are skipped)
    action: weather.get_forecasts
    target:
      entity_id:
        - weather.meteo_france
        - weather.forecast_home
    data:
      type: hourly
    response_variable: forecasts
  - alias: Analyse tomorrow between 8 am and 7 pm
    variables:
      summary: |-
        {% set tomorrow = (now() + timedelta(days=1)).date() %}
        {% set rainy = ['rainy', 'pouring', 'lightning-rainy', 'snowy', 'snowy-rainy', 'hail'] %}
        {% set res = namespace(l=[]) %}
        {% for src in ['weather.meteo_france', 'weather.forecast_home'] if src in forecasts %}
          {% set ns = namespace(rain=[], frost=[], mm=0, peak=0, tmin=none, n=0) %}
          {% for f in forecasts[src].forecast %}
            {% set t = as_local(as_datetime(f.datetime)) %}
            {% if t.date() == tomorrow and 8 <= t.hour <= 18 %}
              {% set ns.n = ns.n + 1 %}
              {% set p = f.precipitation | float(0) %}
              {% if p > 0 or f.condition in rainy %}
                {% set ns.rain = ns.rain + [t.hour] %}
                {% set ns.mm = ns.mm + p %}
                {% if p > ns.peak %}{% set ns.peak = p %}{% endif %}
              {% endif %}
              {% if f.temperature is number %}
                {% if ns.tmin is none or f.temperature < ns.tmin %}{% set ns.tmin = f.temperature %}{% endif %}
                {% if f.temperature <= 0 %}{% set ns.frost = ns.frost + [t.hour] %}{% endif %}
              {% endif %}
            {% endif %}
          {% endfor %}
          {% if ns.n > 0 %}
            {% set sp = namespace(out=[]) %}
            {% for hours in [ns.rain, ns.frost] %}
              {% set r = namespace(l=[], start=none, prev=none) %}
              {% for h in hours %}
                {% if r.start is none %}{% set r.start = h %}
                {% elif h != r.prev + 1 %}{% set r.l = r.l + [[r.start, r.prev + 1]] %}{% set r.start = h %}{% endif %}
                {% set r.prev = h %}
              {% endfor %}
              {% if r.start is not none %}{% set r.l = r.l + [[r.start, r.prev + 1]] %}{% endif %}
              {% set sp.out = sp.out + [r.l] %}
            {% endfor %}
            {% set res.l = res.l + [{'name': 'Météo-France' if src == 'weather.meteo_france' else 'Met.no', 'rain': ns.rain | count > 0, 'rain_hours': ns.rain | count, 'rain_spans': sp.out[0], 'mm': ns.mm | round(1), 'peak': ns.peak | round(1), 'frost': ns.frost | count > 0, 'frost_hours': ns.frost | count, 'frost_spans': sp.out[1], 'tmin': ns.tmin}] %}
          {% endif %}
        {% endfor %}
        {% set with_rain = res.l | selectattr('rain') | list %}
        {% set ref = with_rain | first if with_rain else (res.l | first if res.l else none) %}
        {% set peak = ref.peak if ref else 0 %}
        {% set main = res.l | first if res.l else none %}
        {{ {
          'sources': res.l | count,
          'rain': with_rain | count > 0,
          'risk': none if res.l | count < 2 or not with_rain else ('high' if with_rain | count == 2 else 'uncertain'),
          'only_source': with_rain[0].name if with_rain | count == 1 else '',
          'intensity': 'heavy' if peak >= 4 else ('moderate' if peak >= 1 else 'light'),
          'rain_hours': ref.rain_hours if ref else 0,
          'rain_spans': ref.rain_spans if ref else [],
          'mm': ref.mm if ref else 0,
          'peak': peak,
          'frost': main.frost if main else false,
          'frost_hours': main.frost_hours if main else 0,
          'frost_spans': main.frost_spans if main else [],
          'tmin': main.tmin if main else none
        } }}
  - alias: Continue only if rain or frost
    condition: template
    value_template: "{{ summary.rain or summary.frost }}"
  - alias: Notify the rider
    action: notify.mobile_app_rider_phone
    data:
      title: >-
        {% set days = ['Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday', 'Saturday', 'Sunday'] %}🚲 Bike {{ days[(now() + timedelta(days=1)).weekday()] }}: {{ ('🌧️ ' ~ summary.intensity ~ ' rain') if summary.rain }}{{ ' + ' if summary.rain and summary.frost }}{{ '❄️ frost' if summary.frost }}
      message: |-
        {%- macro when(spans, n) -%}
        {%- if n >= 11 -%}all day, from 8:00 to 19:00
        {%- else -%}
        {%- set m = namespace(l=[]) -%}
        {%- for p in spans -%}
        {%- set m.l = m.l + [('for 1 hour from ' ~ p[0] ~ ':00 to ' ~ p[1] ~ ':00') if p[1] - p[0] == 1 else ('between ' ~ p[0] ~ ':00 and ' ~ p[1] ~ ':00')] -%}
        {%- endfor -%}
        {{ m.l | join(', then ') }}
        {%- endif -%}
        {%- endmacro -%}
        {% set l = namespace(l=[]) %}{% if summary.rain %}{% set s = (summary.intensity | capitalize) ~ ' rain ' ~ when(summary.rain_spans, summary.rain_hours) %}{% if summary.mm > 0 %}{% set s = s ~ ' (' ~ summary.mm ~ ' mm in total, up to ' ~ summary.peak ~ ' mm/h)' %}{% endif %}{% set l.l = l.l + [s ~ '.'] %}{% if summary.risk == 'high' %}{% set l.l = l.l + ['High risk: Météo-France and Met.no both forecast it.'] %}{% elif summary.risk == 'uncertain' %}{% set l.l = l.l + ['Uncertain risk: only ' ~ summary.only_source ~ ' forecasts it.'] %}{% endif %}{% set l.l = l.l + ['Better leave the bike at home.' if summary.intensity == 'heavy' else ('Full rain gear needed.' if summary.intensity == 'moderate' else 'A rain jacket should do.')] %}{% endif %}{% if summary.frost %}{% set l.l = l.l + ['Frost ' ~ when(summary.frost_spans, summary.frost_hours) ~ ', down to ' ~ summary.tmin ~ ' °C: risk of ice on the road.'] %}{% endif %}{{ l.l | join('\n') }}
      data:
        tag: weather_tomorrow
        channel: reminders
        clickAction: entityId:weather.meteo_france
        timeout: "{{ ((today_at('19:00') + timedelta(days=1)) - now()).total_seconds() | int }}"
mode: single
```

</details>

To adapt it, replace the two weather entities with yours (the code skips a source missing from the response) and the alarm sensor with your phone's. The 8 am to 7 pm window and the mm/h thresholds can be changed directly in the code.

### My take: genuinely useful

This notification passed the household approval test straight away. It helps in two situations:

- deciding the night before to leave the bike at home when the forecast is a washout;
- remembering to bring rain gear when it's only light rain in the morning.

## Conclusion

The key to this setup is the threshold: a reminder sent only when needed is more likely to be read than a daily notification. If your Bosch e-bike runs the Smart System and your Bosch account is in the EU, the Bosch eBike integration gives you everything you need to build it. To go further, the README describes an ESP32 Bluetooth bridge that reports the state of charge live.
